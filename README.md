## Содержание

### [Лаба №3. Парадокс ветвления процессов и магия Copy-on-Write](./lab3/)

Изучение системного вызова `fork()` и механизма Copy-on-Write на уровне таблиц страниц и MMU.

**Файлы:**
- `fork_mystery.py` — скрипт с раздвоением процесса
- `run.png` — скриншот работы
- `answers.md` — ответы на 2 контрольных вопроса

**Ключевой результат:** виртуальные адреса переменной у родителя и потомка совпадают (`0xad8350`), но после записи в потомке его адрес меняется (`0x76a020b40c50`), а родитель продолжает видеть старое значение `42`. Это доказывает изоляцию адресных пространств и работу Copy-on-Write.

### [Лаба №4. Race Condition в Python](./lab4/)

Воспроизведение состояния гонки при работе двух потоков с общим счётчиком, а также защита через мьютекс `threading.Lock()`.

**Файлы:**
- `race_condition.py` — версия без синхронизации
- `race_condition_lock.py` — версия с мьютексом
- `no_lock.png` — скриншот без синхронизации
- `with_lock.png` — скриншот с мьютексом
- `answers.md` — ответы на 2 контрольных вопроса

**Ключевой результат:** на Python 3.13 (CPython с GIL) гонка на 1 000 000 итераций **не воспроизводится** — оба запуска дают ровно 2 000 000. Это демонстрирует, что GIL эффективно защищает короткие операции `+=` от прерываний. При добавлении `Lock` время выполнения выросло с ~0.05 сек до ~0.21 сек (в ~4 раза), потому что потоки сериализуются на критической секции.

### [Лаба №5. Race Condition на уровне машинных инструкций (NASM)](./lab5/)

Воспроизведение гонки на чистом ассемблере x86-64 и её аппаратное решение через префикс `lock`.

**Файлы:**
- `race_nasm.asm` — неатомарный инкремент (`mov` / `inc` / `mov`)
- `race_nasm_lock.asm` — атомарный инкремент (`lock inc`)
- `runner.py` — Python-обёртка через `ctypes`, запускающая ассемблерную функцию в двух потоках
- `without_lock.png` — результат без `lock`
- `with_lock.png` — результат с `lock`
- `answers.md` — ответы на 3 контрольных вопроса

**Ключевой результат:**

| | Без `lock` | С `lock` |
|---|---|---|
| Фактический результат | 10 630 267 | 20 000 000 |
| Потеряно инкрементов | 9 369 733 (~47%) | 0 |
| Время выполнения | 0.0173 сек | 0.1819 сек |
| Замедление | — | ~10.5× |

Гонка на ассемблере проявляется **грубо** — теряется почти половина инкрементов. Инструкция `lock inc` полностью решает проблему, но замедляет программу в ~10 раз из-за аппаратной блокировки кэш-линии и сериализации доступа.

## Как запускать

### Лаба №3 (WSL/Linux)
```bash
cd lab3
python3 fork_mystery.py
```

### Лаба №4 (Windows)
```cmd
cd lab4
python race_condition.py
python race_condition_lock.py
```

### Лаба №5 (WSL/Linux)
```bash
cd lab5
nasm -f elf64 race_nasm.asm -o race_nasm.o
gcc -shared -pthread race_nasm.o -o librace.so
python3 runner.py

# Версия с lock:
nasm -f elf64 race_nasm_lock.asm -o race_nasm.o
gcc -shared -pthread race_nasm.o -o librace.so
python3 runner.py
```
